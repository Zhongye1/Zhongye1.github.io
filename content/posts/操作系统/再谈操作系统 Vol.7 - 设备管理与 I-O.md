计算机可以连接大量输入输出设备：键盘、鼠标、显示器、网卡、硬盘、打印机、音响等。不同设备的用法和功能差异很大，操作系统需要一层层抽象，才能用统一的方式管理它们。

设备管理的关键层次如下：

- **设备控制器**：位于设备一侧，屏蔽设备差异，CPU 通过读写控制器中的寄存器与设备交互；
- **设备驱动程序**：位于操作系统内核，面向设备控制器，负责发出控制指令、处理中断；
- **通用块层**：位于文件系统与块设备驱动之间，为块设备提供统一抽象，并对 I/O 请求排队和调度；
- **I/O 控制方式**：轮询、中断和 DMA，决定 CPU 如何得知 I/O 完成、如何参与数据传输。

最后以「键盘敲入字母 A」为例，把设备控制器、中断、驱动程序、缓冲区队列和显示设备串起来，观察一次输入从硬件到屏幕的完整路径。

## 设备控制器

为了屏蔽设备之间的差异，每个设备都有一个**设备控制器**（Device Controller）。硬盘有硬盘控制器，显示器有视频控制器，键盘有键盘控制器。控制器了解对应设备的用法和功能，CPU 通过设备控制器与设备打交道。

![计算机 I/O 系统结构](https://cdn.xiaolincoding.com/gh/xiaolincoder/ImageHost2/%E6%93%8D%E4%BD%9C%E7%B3%BB%E7%BB%9F/%E8%BE%93%E5%85%A5%E8%BE%93%E5%87%BA/I_O%E7%B3%BB%E7%BB%9F%E7%BB%93%E6%9E%84.png)

设备控制器内部有芯片，可以执行自己的逻辑，也有自己的寄存器，用于与 CPU 通信：

- 操作系统向寄存器写入数据，可以命令设备发送数据、接收数据、开启或关闭，或执行其他操作；
- 操作系统读取寄存器，可以了解设备状态，例如是否准备好接收新命令。

控制器通常有三类寄存器：

- **数据寄存器**：CPU 向 I/O 设备写入需要传输的数据。例如要打印「Hello」，CPU 先发送字符 `H` 给对应的 I/O 设备；
- **命令寄存器**：CPU 发送命令，告诉 I/O 设备要执行输入或输出操作；任务完成后，状态寄存器中的状态被标记为完成；
- **状态寄存器**：告诉 CPU 设备正在工作或工作已经完成。如果设备正在工作，CPU 再发送数据或命令都没有用；直到前一个工作完成、状态标记为完成，CPU 才能发送下一个字符和命令。

![设备控制器的寄存器](https://cdn.xiaolincoding.com/gh/xiaolincoder/ImageHost2/%E6%93%8D%E4%BD%9C%E7%B3%BB%E7%BB%9F/%E8%BE%93%E5%85%A5%E8%BE%93%E5%87%BA/%E8%AE%BE%E5%A4%87%E6%8E%A7%E5%88%B6%E5%99%A8.png)

CPU 通过读写设备控制器中的寄存器控制设备，比直接控制输入输出设备更方便、更标准。

输入输出设备可分为两大类：

- **块设备**（Block Device）：把数据存储在固定大小的块中，每个块有自己的地址，硬盘、USB 是常见的块设备；
- **字符设备**（Character Device）：以字符为单位发送或接收字符流，字符设备不可寻址，也没有寻道操作，鼠标是常见的字符设备。

块设备通常传输的数据量很大，因此控制器会设置一个可读写的数据缓冲区：

- CPU 写入数据到控制器缓冲区时，缓冲区数据积累到一部分后，才发给设备；
- CPU 从控制器缓冲区读取数据时，也需要缓冲区积累到一部分，才拷贝到内存。

这样做是为了减少对设备的频繁操作。

CPU 与设备控制器的寄存器和数据缓冲区通信，有两种方式：

- **端口 I/O**：每个控制寄存器分配一个 I/O 端口，通过特殊的汇编指令操作这些寄存器，例如 `in`、`out`；
- **内存映射 I/O**：把所有控制寄存器映射到内存空间，这样就可以像读写内存一样读写数据缓冲区。

## I/O 控制方式

每种设备都有设备控制器，控制器相当于一个小 CPU，可以自己处理一些事情。但 CPU 给设备发送指令后，设备控制器读完数据，需要通知 CPU。常见的 I/O 控制方式有三种：轮询、中断和 DMA。

### 轮询

控制器的寄存器一般会有状态标记位，用来标识输入或输出操作是否完成。第一种方法是**轮询等待**：CPU 一直检查寄存器状态，直到状态标记为完成。

这种方式实现简单，但会占用 CPU 的全部时间，效率很低。

### 中断

第二种方法是**中断**：设备完成任务后通知操作系统数据已经准备好。

通常有一个硬件**中断控制器**。设备完成任务后触发中断到中断控制器，中断控制器通知 CPU：一个中断产生了，CPU 需要停下当前工作来处理中断。

中断有两种：

- **软中断**：例如代码调用 `INT` 指令触发；
- **硬件中断**：硬件通过中断控制器触发。

对于频繁读写数据的磁盘，中断方式并不友好：CPU 容易经常被打断，占用大量 CPU 时间。这类设备可以使用 DMA。

### DMA

**DMA**（Direct Memory Access）可以让设备在 CPU 不参与的情况下，自行完成把设备 I/O 数据放入内存。实现 DMA 需要「DMA 控制器」硬件的支持。

![DMA 工作原理](https://cdn.xiaolincoding.com/gh/xiaolincoder/ImageHost2/%E6%93%8D%E4%BD%9C%E7%B3%BB%E7%BB%9F/%E8%BE%93%E5%85%A5%E8%BE%93%E5%87%BA/DMA%E5%B7%A5%E4%BD%9C%E5%8E%9F%E7%90%86.png)

DMA 的工作方式如下：

1. CPU 向 DMA 控制器下发指令，告诉它要读取多少数据，读完的数据放在内存的某个位置；
2. DMA 控制器向磁盘控制器发出指令，通知它从磁盘读数据到内部缓冲区；
3. 磁盘控制器把缓冲区的数据传输到内存；
4. 传输完成后，磁盘控制器在总线上发出确认成功的信号给 DMA 控制器；
5. DMA 控制器收到信号后，发中断通知 CPU 指令完成，CPU 可以直接使用内存中的数据。

使用 DMA 读取磁盘数据时，CPU 只需给 DMA 控制器发送指令，然后返回去做其他事情；磁盘数据拷贝到内存后，DMA 控制器通过中断通知 CPU。整个过程中，只有传送开始和结束时需要 CPU 干预。

## 设备驱动程序

设备控制器屏蔽了设备的许多细节，但每种设备的控制器在寄存器、缓冲区等使用模式上仍然不同。为了屏蔽「设备控制器」的差异，操作系统引入了**设备驱动程序**。

设备控制器属于硬件，不属于操作系统；设备驱动程序属于操作系统的一部分。操作系统的内核代码可以像调用本地代码一样使用设备驱动程序的接口；设备驱动程序面向设备控制器，发出操控设备控制器的指令后，才能操作设备。

不同设备控制器的功能不同，但设备驱动程序会向操作系统提供统一的接口。这样不同的设备驱动程序可以以相同的方式接入操作系统。

![设备驱动程序接口的一致性](https://cdn.xiaolincoding.com/gh/xiaolincoder/ImageHost2/%E6%93%8D%E4%BD%9C%E7%B3%BB%E7%BB%9F/%E8%BE%93%E5%85%A5%E8%BE%93%E5%87%BA/%E9%A9%B1%E5%8A%A8%E7%A8%8B%E5%BA%8F%E6%8E%A5%E5%8F%A3%E4%B8%80%E8%87%B4%E6%80%A7.png)

设备完成任务后会发送中断通知操作系统。操作系统需要一个地方处理中断，这个地方就在设备驱动程序中。驱动程序会及时响应控制器发来的中断请求，并根据中断类型调用相应的**中断处理程序**。

通常，设备驱动程序初始化时，会先注册该设备的中断处理函数。

![中断处理过程](https://cdn.xiaolincoding.com/gh/xiaolincoder/ImageHost2/%E6%93%8D%E4%BD%9C%E7%B3%BB%E7%BB%9F/%E8%BE%93%E5%85%A5%E8%BE%93%E5%87%BA/%E4%B8%AD%E6%96%AD%E5%B7%A5%E4%BD%9C%E8%BF%87%E7%A8%8B.png)

中断处理程序的处理流程：

1. I/O 时，设备控制器如果已经准备好数据，通过中断控制器向 CPU 发送中断请求；
2. 保护被中断进程的 CPU 上下文；
3. 转入相应的设备中断处理函数；
4. 进行中断处理；
5. 恢复被中断进程的上下文。

## 通用块层与 I/O 调度

对于块设备，为了减少不同块设备差异带来的影响，Linux 通过统一的**通用块层**管理不同的块设备。

这里的 I/O 调度器与 Vol.5 的磁盘调度算法处于不同层次：前者在通用块层对请求排队、合并和排序，后者描述磁头如何移动以缩短寻道距离。

通用块层位于文件系统和磁盘驱动之间，是一个块设备抽象层，主要有两个功能：

- 向上为文件系统和应用程序提供访问块设备的标准接口；向下把不同的磁盘设备抽象为统一的块设备，并在内核层面提供一个框架来管理这些设备的驱动程序；
- 对文件系统和应用程序发来的 I/O 请求排队，并对队列重新排序、合并请求，也就是 **I/O 调度**，目的是提高磁盘读写效率。

Linux 内核传统上支持 5 种 I/O 调度算法：

- 没有调度算法；
- 先入先出调度算法；
- 完全公平调度算法；
- 优先级调度；
- 最终期限调度算法。

**没有调度算法**：不对文件系统和应用程序的 I/O 做任何处理。这种算法常用在虚拟机 I/O 中，此时磁盘 I/O 调度交由物理机系统负责。

**先入先出调度算法**：最简单的 I/O 调度算法，先进入 I/O 调度队列的请求先发生。

**完全公平调度算法**：为每个进程维护一个 I/O 调度队列，并按照时间片均匀分布每个进程的 I/O 请求。大部分系统曾把它作为默认 I/O 调度器。

**优先级调度算法**：优先级高的 I/O 请求先发生，适用于运行大量进程的系统，例如桌面环境、多媒体应用。

**最终期限调度算法**：分别为读、写请求创建不同的 I/O 队列，可以提高机械磁盘的吞吐量，并确保到达最终期限的请求被优先处理，适用于 I/O 压力较大的场景，例如数据库。

现代 Linux 内核引入了多队列 I/O 调度器，具体可用算法会随内核版本和配置变化；上述五类主要用于理解 I/O 调度的基本思路。

## 存储系统 I/O 软件分层

结合设备、设备控制器、驱动程序和通用块层，Linux 存储系统的 I/O 软件可以由上到下分为三层：文件系统层、通用块层、设备层。

![Linux 存储系统 I/O 软件分层](https://cdn.xiaolincoding.com/gh/xiaolincoder/ImageHost2/%E6%93%8D%E4%BD%9C%E7%B3%BB%E7%BB%9F/%E8%BE%93%E5%85%A5%E8%BE%93%E5%87%BA/I_O%E8%BD%AF%E4%BB%B6%E5%88%86%E5%B1%82.png)

三层的作用：

- **文件系统层**：包括虚拟文件系统和其他文件系统的具体实现。向上为应用程序提供标准的文件访问接口，向下通过通用块层存储和管理磁盘数据；
- **通用块层**：包括块设备的 I/O 队列和 I/O 调度器。对文件系统的 I/O 请求排队，再通过 I/O 调度器选择一个 I/O 发给设备层；
- **设备层**：包括硬件设备、设备控制器和驱动程序，负责最终物理设备的 I/O 操作。

有了文件系统接口，不但可以通过文件系统命令行操作设备，也可以通过应用程序调用 `read`、`write`，像读写文件一样操作设备。因此，设备在 Linux 下也是一个特殊的文件。

除了读写操作，还需要检查特定设备的功能和属性，于是有了 `ioctl` 接口。它表示输入输出控制接口，是用于配置和修改特定设备属性的通用接口。

存储系统 I/O 是整个系统最慢的环节之一，因此 Linux 提供了多种缓存机制：

- 为了提高文件访问效率，使用**页缓存、索引节点缓存、目录项缓存**等，减少对块设备的直接调用；
- 为了提高块设备访问效率，使用**缓冲区**缓存块设备的数据。

## 键盘敲入字母时发生了什么

下面从操作系统角度追踪一次键盘输入：用户按下字母 `A`，到字符显示在屏幕上，期间发生了什么。

CPU 的硬件架构如下图所示：

![CPU 硬件总线图](https://cdn.xiaolincoding.com/gh/xiaolincoder/ImageHost2/%E6%93%8D%E4%BD%9C%E7%B3%BB%E7%BB%9F/%E8%BE%93%E5%85%A5%E8%BE%93%E5%87%BA/CPU%20%E7%A1%AC%E4%BB%B6%E6%80%BB%E7%BA%BF%E5%9B%BE.png)

CPU 内部的内存接口直接与系统总线通信；系统总线接入 I/O 桥接器，I/O 桥接器另一边接入内存总线，使 CPU 与内存通信；再另一边接入 I/O 总线，用来连接键盘、显示器等 I/O 设备。

当用户输入键盘字符时：

1. **键盘控制器产生扫描码**：键盘控制器产生扫描码数据，并将其缓冲在键盘控制器的寄存器中；
2. **发送中断请求**：键盘控制器通过总线向 CPU 发送中断请求；
3. **保存上下文**：CPU 收到中断请求后，操作系统保存被中断进程的 CPU 上下文；
4. **调用键盘中断处理程序**：操作系统调用键盘的中断处理程序。该处理程序是在键盘驱动程序初始化时注册的；
5. **读取扫描码并翻译**：中断处理函数从键盘控制器的寄存器缓冲区读取扫描码，再根据扫描码找到用户输入的字符。如果输入的是显示字符，就把扫描码翻译成对应的 ASCII 码。例如输入字母 `A`，就翻译成 `A` 的 ASCII 码；
6. **放入读缓冲区队列**：得到显示字符的 ASCII 码后，把它放入「读缓冲区队列」；
7. **显示字符**：显示设备的驱动程序定时从「读缓冲区队列」读取数据，放到「写缓冲区队列」，再把「写缓冲区队列」的数据逐个写入显示设备控制器的数据缓冲区，最终显示在屏幕上；
8. **恢复上下文**：显示完成后，恢复被中断进程的上下文。

这条路径把设备管理的几个层次串了起来：

- 键盘控制器负责产生扫描码和中断；
- 键盘驱动程序负责注册中断处理函数、读取扫描码并翻译字符；
- 读缓冲区队列和写缓冲区队列连接输入设备与显示设备；
- 显示设备控制器负责最终把字符输出到屏幕。

## ED

设备管理通过分层屏蔽硬件差异：

- 设备控制器把设备操作抽象为寄存器读写；
- 设备驱动程序把不同控制器的差异封装为统一接口，并处理中断；
- 通用块层为块设备提供统一抽象，通过 I/O 调度优化请求顺序；
- 文件系统层向上提供文件接口，使设备也可以像文件一样被读写。

I/O 控制方式则决定了 CPU 的参与程度：

- 轮询实现简单，但浪费 CPU；
- 中断适合低频、事件驱动的设备；
- DMA 适合磁盘等大批量数据传输，CPU 只在开始和结束时介入。

一次键盘输入看似简单，背后却经过了设备控制器、中断控制器、驱动程序、缓冲区队列和显示控制器等多个环节。
