![昼夜切换效果](https://pic2.zhimg.com/v2-44560abcaa5475912b0cc50e3f3cc2d1_b.webp)

UnoCSS 官网在点击按钮切换深浅主题时，会以鼠标点击的位置为圆心，把一个圆形向外扩散开，铺满整屏后完成换色。这个效果用 View Transition API 写下来全部代码不到 50 行，不需要任何动画库。

## 一、View Transition API

View Transition API 提供了一种机制，让我们在更新 DOM 内容的同时，创建不同 DOM 状态之间的动画过渡。

1. **截图旧状态**：调用 `document.startViewTransition()` 时，浏览器会立即截取当前页面的「屏幕截图」，保存为旧视图；
2. **回调里更新 DOM**：该方法接收一个回调函数，我们在其中完成状态更新（比如切换主题 class），浏览器渲染出新的 DOM 结构后同样会截图，作为新视图；
3. **暴露伪元素**：浏览器把两张截图分别挂到一组伪元素上——`::view-transition-old` 是旧页面的截图，`::view-transition-new` 是新页面的截图。

伪元素树结构：

```text
::view-transition
└─ ::view-transition-group(root)
   └─ ::view-transition-image-pair(root)
      ├─ ::view-transition-old(root)   ← 旧快照
      └─ ::view-transition-new(root)   ← 新快照
```

自定义动画就是在这棵树上做文章。

默认情况下，浏览器会为这两个伪元素播放一段交叉淡入淡出，而我们要做的自定义过渡，本质上就是**用 CSS/JS 接管这两个伪元素的动画**。

基于这个「截图 → 换图 → 放动画」的模型，接下来就很容易做出这个效果了。

本博客 https://blog.junce.net/ 的昼夜切换效果也是基于这个原理

## 二、接入默认过渡

先写一个没有任何动画的基础案例：页面里准备两套 CSS 主题变量，通过在根元素上切换 `dark` class 来改变配色，点击按钮时主题瞬间「跳变」。接入 View Transition 只需要把状态更新包一层：

```html
<style>
  :root {
    --background-color: #ffffff;
    --text-color: #1a1a1a;
  }
  :root.dark {
    --background-color: #000000;
    --text-color: #f5f5f5;
  }
  body {
    background-color: var(--background-color);
    color: var(--text-color);
  }
</style>
<body>
  <button id="btn">Toggle Theme</button>
  <script>
    const btn = document.querySelector('#btn')
    btn.addEventListener('click', () => {
      document.startViewTransition(() => {
        document.documentElement.classList.toggle('dark')
      })
    })
  </script>
</body>
```

主题切换就从生硬的跳变变成了默认的**淡入淡出**。

回调除了同步函数，也可以返回一个 Promise——浏览器会等它 resolve 之后才去拍新快照，这个特性后面会用到。

## 三、圆形扩散动画

「圆形扩散」的思路是：对新页面的截图做 `clip-path` 圆形裁剪，让裁剪半径从 0 逐渐放大到能覆盖全屏。

```js
btn.addEventListener('click', () => {
  // 拿到 transition 实例
  const transition = document.startViewTransition(() => {
    document.documentElement.classList.toggle('dark')
  })

  // ready 是一个 Promise，在动画即将开始时 resolve
  transition.ready.then(() => {
    document.documentElement.animate(
      {
        clipPath: ['circle(0% at 50% 50%)', 'circle(100% at 50% 50%)'],
      },
      {
        duration: 600,
        pseudoElement: '::view-transition-new(root)', // 关键：动画作用在新截图伪元素上
      },
    )
  })
})
```

这里有三点：

- **`transition.ready`**：它是一个 Promise，在过渡动画即将开始的那一刻 resolve，自定义动画必须在它的 `.then()` 里创建，时机才正确；
- **`pseudoElement` 选项**：我们要过渡的对象是「新页面的截图」（伪元素 `::view-transition-new(root)`），而不是真实 DOM，所以必须通过 `animate` 的 `pseudoElement` 选项把动画指过去；
- **关掉默认动画**：不关掉浏览器默认的淡入淡出，它会和我们挂的 `clip-path` 叠在一起，得在 CSS 里显式声明 `animation` 把它顶掉：

```css
::view-transition-old(root),
::view-transition-new(root) {
  animation: none;
}
```

UA 样式表的优先级最低，普通声明就压得住，这里的 `animation` 不需要加 `!important`。

## 四、圆心对准鼠标点击位置

`circle(0% at 50% 50%)` 的圆心固定在屏幕正中央，而设计目标是**从点击按钮的位置扩散**。解决方式是利用点击事件对象里的坐标，把硬编码的 `50% 50%` 换成动态的像素坐标：

```js
btn.addEventListener('click', (event) => {
  const { clientX: x, clientY: y } = event

  const transition = document.startViewTransition(() => {
    document.documentElement.classList.toggle('dark')
  })

  transition.ready.then(() => {
    document.documentElement.animate(
      {
        clipPath: [`circle(0px at ${x}px ${y}px)`, `circle(100% at ${x}px ${y}px)`],
      },
      { duration: 600, pseudoElement: '::view-transition-new(root)' },
    )
  })
})
```

`clip-path` 的 `circle()` 支持用 `at x y` 指定圆心，动画的起点就自然贴合了用户的点击位置。`clientX/clientY` 是相对视口的坐标，而快照用的正是视口坐标系，拿来直接用即可。

## 五、用三角函数计算最大半径

上面的终点半径还写着 `100%`。百分比半径的参考长度是 `sqrt(宽² + 高²) / √2`，只跟视口尺寸有关，和圆心在哪无关：点屏幕角落时最远角的距离是整条对角线，也就是参考长度的 141%，`100%` 必然盖不满。写死一个 `150%` 倒是能兜住（最坏情况需要 141%），但点击点越靠近屏幕中间浪费得越多——半径可能比实际需要大出将近一半，动画后段圆早就铺满屏幕了，剩下的时间都在「空转」。

要刚好盖住，得算出**从点击点到屏幕最远那个角的距离**：以点击点为直角顶点，水平直角边是点击点到屏幕左右边的最大距离，垂直直角边是到屏幕上下边的最大距离，斜边（半径）用勾股定理求出，即 `Math.hypot`。

```text

              ┌───────────────────┐
              │       │           │
              │  A    │    B      │
              │       ●(x,y)      │
 innerHeight  │       │           │
              │───────┼───────────┤
              │  C    │    D      │
              │       │           │
              └───────┴───────────┘← 最远角
                  innerWidth
```

从点击点 `(x, y)` 到四个角的水平/垂直距离分别是 `x` 与 `window.innerWidth - x`、`y` 与 `window.innerHeight - y`。取各轴的**最大值**再求斜边，就是能覆盖全屏的最小半径：

```js
const dx = Math.max(x, window.innerWidth - x)
const dy = Math.max(y, window.innerHeight - y)
const endRadius = Math.hypot(dx, dy)
```

代回 `clipPath`，终点就写成 `circle(${endRadius}px at ${x}px ${y}px)`。

## 六、让两个方向都有动画

到这一步，动画只加在 `::view-transition-new(root)` 上：由浅色切到深色时，是新快照（深色）从点击处扩散开。反过来由深色切回浅色时，如果还动新快照，看到的就是浅色从点击处扩散——但用户的心理预期是「天亮了」，应该是深色向圆心收拢、退回点击的那个点，浅色从四周推进来。

所以要按方向分开处理：

- **浅色 → 深色**：动新快照，`clip-path` 从 0 扩到 `endRadius`；
- **深色 → 浅色**：动旧快照（深色），`clip-path` 从 `endRadius` 收回到 0。

问题在于默认层级：`::view-transition-new(root)` 在 `::view-transition-old(root)` 之上。只动新快照时它天然在最上层，但**深色 → 浅色**要动的是旧快照，就得先把它抬上来。

最省事的做法是用两个自定义属性，让 `z-index` 跟着主题一起翻转——切到夜间时新快照在上，切回日间时旧快照在上，正好每次都是「该动的那张」压住另一张：

```css
:root {
  --background-color: #ffffff;
  --text-color: #1a1a1a;
  /* 日间：动旧快照，所以旧快照在上 */
  --vt-old-z: 9999;
  --vt-new-z: 1;
}

:root.dark {
  --background-color: #000000;
  --text-color: #f5f5f5;
  /* 夜间：动新快照，所以新快照在上 */
  --vt-old-z: 1;
  --vt-new-z: 9999;
}

::view-transition-old(root) {
  z-index: var(--vt-old-z);
  animation: none;
}

::view-transition-new(root) {
  z-index: var(--vt-new-z);
  animation: none;
}
```

两张快照同在 `::view-transition-image-pair(root)` 这个层叠上下文里，直接改 `z-index` 就能换顺序。

接着让 `startViewTransition` 根据主题状态，为不同的伪元素挂动画：

```ts
const REVEAL_DURATION = 600

/** 切换明暗主题，圆形揭示从 event 的坐标开始 */
function toggleTheme(event: MouseEvent) {
  const x = event.clientX
  const y = event.clientY
  // 圆要盖住整屏：半径取圆心到最远那个角的距离
  const endRadius = Math.hypot(
    Math.max(x, window.innerWidth - x),
    Math.max(y, window.innerHeight - y),
  )

  // 目标主题在开转场之前就定下来，ready 里直接用它判断方向
  const toDark = !isDark.value

  const transition = document.startViewTransition(async () => {
    isDark.value = toDark
    // 等主题类真正落到 <html> 上，再让浏览器去拍新快照
    await nextTick()
  })

  transition.ready.then(() => {
    const clipPath = [`circle(0px at ${x}px ${y}px)`, `circle(${endRadius}px at ${x}px ${y}px)`]

    document.documentElement.animate(
      {
        clipPath: toDark ? clipPath : clipPath.reverse(),
      },
      {
        duration: REVEAL_DURATION,
        easing: 'cubic-bezier(.76,.32,.29,.99)',
        // 变夜间动新快照（深色扩散进来），变日间动旧快照（深色收拢回去）
        pseudoElement: toDark ? '::view-transition-new(root)' : '::view-transition-old(root)',
      },
    )
  })
}
```

这里的 `isDark` 用的是 VueUse 的 `useDark()`（由它负责在 `<html>` 上增删 `dark` 类），`nextTick` 来自 Vue。换成别的方式管理主题也一样，只要保证类名在回调里真正落到 DOM 上就行。

## 七、几个坑

### 1. 默认动画里还藏着混合模式

只写 `mix-blend-mode: normal` 压不住默认效果：Chrome 的 UA 样式表里有一条 `-ua-mix-blend-mode-plus-lighter` 关键帧，混合模式是**连同默认动画一起施加**的。两张不透明快照相加，浅色下会直接过曝成一片白。所以显式声明 `animation` 这一步不只是为了去掉淡入淡出，也是让 `mix-blend-mode: normal` 真正生效的前提：

```css
::view-transition-old(root),
::view-transition-new(root) {
  animation: none;
  mix-blend-mode: normal;
}
```

想确认这条 UA 动画的话，在 DevTools 里选中 `::view-transition-new(root)`，看一眼它的 animation 列表即可。

### 2. `ready` 里挂动画，会先闪一帧整屏浅色

伪元素从建好到 `ready` resolve 之间至少隔了一帧，而这一帧里新快照是按「没有裁切」画的。由深转浅时那一帧就是整屏浅色，观感是「先白一下，再从圆心展开」；由浅转深反而看不出来，因为那一帧的旧快照本来就长这样。

解决方式是把动画从 WAAPI 挪进样式表：在 `startViewTransition` **之前**把圆心和半径写到 `<html>` 的自定义属性上，伪元素一建出来就已经是裁到 0 的状态了。

```css
@property --reveal-x {
  syntax: '<length>';
  inherits: true;
  initial-value: 50vw;
}

@property --reveal-y {
  syntax: '<length>';
  inherits: true;
  initial-value: 50vh;
}

@property --reveal-r {
  syntax: '<length>';
  inherits: true;
  initial-value: 100vmax;
}

@keyframes theme-reveal-expand {
  from {
    clip-path: circle(0px at var(--reveal-x) var(--reveal-y));
  }
  to {
    clip-path: circle(var(--reveal-r) at var(--reveal-x) var(--reveal-y));
  }
}
```

另外还有兼容性方面，单文档视图过渡目前 Chrome / Edge 111+、Safari 18+、Firefox 144+（143 默认关闭）可用，[caniuse](https://caniuse.com/view-transitions) 给出的全球覆盖率约 92%。不支持的浏览器会退化成瞬间切换，功能不受影响。
